## 排查「预处理是不是有问题」——已定位两处独立缺陷（17:00）

**现象**：真机智能体导入 `全员综合复审题库-气化.xlsx`，两次 `import_start(sheetMode=best)`
都报 `totalRows=3, imported=0, duplicated=3`，真正 131 行的题库表根本没被导入。

**证据**（`.workbuddy/tmp/qb.xlsx` 解析 + `.workbuddy/tmp/agent_history.json` 转录）：
文件共 3 张表 —— `Sheet1`(index 0, **4 行**, 表头 关键字/题型/难度/分数/题目内容/可选项/答案/文件名称/父题行号,
3 行示例题)、`模板说明`(index 1, 2 行, 无关键词)、`气化（1-24）`(index 2, **131 行**, 表头与前表**几乎相同**)。
agent 转录里的「系统已解析」注入块只含 3 行示例 —— 即只有 Sheet1。

**缺陷 A（主因）｜预解析只读第一张表**
`FileContentExtractor.extractExcelContent()`(`util/fileparser/FileContentExtractor.java:173`)
→ `OfficeParserUtil.parseExcelFirstSheet(tempFile)`
→ `OfficeParserUtil.java:133-135` → `parseExcel(file, 0)`，**硬编码 sheetIndex=0**。
全项目仅此一处调用 `parseExcelFirstSheet`。
于是多表题库被"预览"成第 0 张表；`formatExcelData()` 1000 行截断与此无关（131<1000）。

**缺陷 B（放大器）｜提示词劝阻 agent 复查**
注入文案 `h_fe85860b`（strings_migrated.xml / chatkit strings.xml）：
"以上 %d 个附件的内容已由系统解析完成并直接提供，请基于上述内容直接回答，**无需再调用解析工具**"。
agent 因此不重新读表，无法发现还有 131 行的表。→ 上一轮加的提示词（用 excel_tool 比行数）
被这句话压制，**修提示词不足以解决问题**。

**缺陷 C（让错误落地）｜pickBestSheet 平手时取先出现的表**
`QuestionImportTaskManager.pickBestSheet()`(`ai/importing/QuestionImportTaskManager.java:229-256`)
只按 `HEADER_KEYWORDS` 表头命中计分（`:215-223`），**不看行数**，且 `if (score > bestScore)` 严格大于
→ 平手保留先遍历到的表。Sheet1 与 气化（1-24）表头同分 → **Sheet1(index 0) 胜出** → totalRows=3。
`sheetMode=all`（默认全扫）本可覆盖 131 行，但 agent 用了 best。此缺陷独立于 A/B，即使 A/B 修好仍会选中 Sheet1。

**结论**：预处理确有 bug（缺陷 A+B），且导入侧还有独立 bug（缺陷 C）。尚未改动任何代码，等用户定方向。
