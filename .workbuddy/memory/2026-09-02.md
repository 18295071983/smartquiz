## 代码走查：思考内容（thinking）检测机制梳理（只读，未改代码）

结论：Java 层**有**检测逻辑，但**全部是硬编码字面量匹配**，且同一职责有 5 套并行实现，规则互相不一致。

### 非硬编码的两条正确路径
- `src/main/cpp/native-lib.cpp:3327`：chatJson 路径用 `mThinkStartTag` / `mThinkEndTags`（从 chat template 提取），
  模板缺失才回退硬编码 `" thinking"` / `" response"`。native 侧还有完整 `stripThinkTags()`（:242，支持未闭合 + `<thought>`）。
- `OnlineInferenceService.java`：在线模型解析 SSE delta 的 `reasoning_content` 协议字段（:1227 / :2205），不猜标签。

### Java 层 5 处硬编码实现
1. `ai/chat/parser/OutputRouter.java` — 状态机；`THINK_END_MARKER="[THINK_END]"` + `<think>`/`</think>`；有 `thinkingEnabled` 隐式进入思考。
2. `ai/chat/streaming/StreamingTokenPipeline.java` — 另一套状态机；额外认 `<|thinking_start|>`/`<|thinking_end|>`，支持同 token 内开闭。
3. `ai/chat/lifecycle/GenerationLifecycleManager.java:96-103` — 最粗：`token.contains("<think>")` 后置 `return`，
   **标签所在 token 的正文一起被丢弃**；且不认 `<|thinking_*|>`。
4. `ui/activity/AIChatActivity.java:5693+`（legacy 回退路径，OutputRouter 为空时启用）+ `AIChatViewModel.java:566` 各判一次 `[THINK_END]`。
5. `ai/chat/ChatAdapter.java:935 / :2889` — 渲染前正则 `<think[^>]*>` 剥离，事后补救。

### 已识别缺陷（未修复，等用户确认）
- 跨 token 标签漏检：Java 三处均单 token `contains()` 判定，标签被 tokenizer 拆开就失效（native 用累积 `collectedText` 更稳）。
- 标签清单不一致：`<thought>` 只有 native 认；`<|thinking_start|>` 只有 StreamingTokenPipeline 认。
- GenerationLifecycleManager 丢内容（见上）。
- native 已剥离标签的 chatJson 路径与老 generateStream 路径标签行为不同 → Java 被迫双写兜底。

### 建议（待确认再动）
统一为一个 `ThinkingTagParser`（可配置标签表 + 跨 token 缓冲 + 与 native `stripThinkTags` 同一套规则），
其余 4 处改为委托；`[THINK_END]` 这类 magic token 收敛为单一常量。
