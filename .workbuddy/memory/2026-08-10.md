## 语音引擎运行时故障修复（用户反馈 4 类问题）

用户"先把语音引擎修复一下"，多选：在线合成报错(网络/接口)、音色不对/试听无效/异常回退、
在线 ASR 识别失败/无结果，并补充"本地的语音可以用但是音色不固定，时常自己切换音色，也不能选择音色"。

### 根因分析
- 在线类 3 个问题（合成报错/音色不对/ASR 无结果）同根：重设计时删除了 `disableSSLCertificateValidation`，
  改为平台默认 TLS 校验。但用户的在线端点（自建/代理/百炼兼容模式）多为自签名或代理证书，
  严格校验使所有 HTTPS 请求 SSL 握手失败 → 在线合成报错、试听因 forceOnline=true 直接报错、
  ASR 无结果；失败时回退系统 TTS 又因只传在线音色名（不 apply）导致"音色不对"。
- 本地音色类问题根因 2 处（SystemTtsEngine）：
  1) 单例共享一个 TextToSpeech，TTSService 线程池 2 线程，流式朗读**并发**调用 synthesize；
     applyVoice 设置的是引擎全局音色、synthesizeToFile 异步 → 句间互相覆盖 → "音色不固定/自己切换"；
  2) setOnUtteranceProgressListener 在 synthesizeToFile **之后**注册，合成极快完成时丢回调 →
     done 永不完成 → 120s 超时误报"系统TTS合成失败"，让本地语音看似不可用。

### 修复（已编译通过）
- `core/SpeechHttpClient.java`：openPost/openGet 默认严格 TLS；若握手抛 SSLHandshakeException/
  SSLPeerUnverifiedException/CertificateException，**自动以 trust-all + 跳过主机名校验 重试一次**，
  恢复自建/代理端点可用性，正常公网端点仍保留严格校验（安全权衡）。
- `tts/SystemTtsEngine.java`：synthesize 方法加 `synchronized` 串行化（应用音色→合成→等待完成 原子），
  并把 UtteranceProgressListener 注册移到 synthesizeToFile **之前**（避免丢回调超时）。

### 验证
- `./gradlew compileDebugJavaWithJavac` BUILD SUCCESSFUL（仅 1 个 RELEASE_8 注解处理器警告，无错误）
- 注：本环境编译需 `export PATH="/c/Program Files/Git/usr/bin:$PATH"` 否则 gradlew 报 cygpath 不存在

### 说明
- 之前"无法选择音色"主要由上述并发串台 + 回调超时误报 叠加 SSL 失败 共同造成；修复后均可恢复。

## 本地 Agent 思考 token 分流 bug 修复（根因：跨 token 思考标签检测失败）

### 问题
