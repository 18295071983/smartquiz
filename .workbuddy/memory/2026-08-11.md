# 2026-08-11 工作日志

## TTS 试听返回空音频 —— 根因与修复（语音文件）

### 现象
- 语音合成「试听」返回空音频；百炼/OpenAI 平台查不到任何调用记录。
- 设备日志（logcat_tts_test.txt）显示：官方 SDK 把请求打到
  `/api/v1/services/audio/tts/SpeechSynthesizer` → `HTTP 400 url error`；
  且模型名被误用为 ASR 模型 `fun-asr-flash-2026-06-15`。

### 根因
- `TTSService.pickEngine` 用 `isDashScopeEndpoint` 判断，只要 URL 含 `maas.aliyuncs.com`
  就走 `DashScopeTtsEngine`（官方 SDK 原生网关）。但百炼**专属实例 / 兼容模式**端点
  （`*.maas.aliyuncs.com/compatible-mode/v1`）只有 OpenAI 兼容 `/audio/speech`，
  没有原生网关路径 → 请求被拒、空音频、平台无记录。
- 用户实际用的是 **OpenAI 兼容协议**，应走 `OpenAiTtsEngine`。

### 修复（仅语音文件，未碰 usage 目录）
1. `TTSService.java` `pickEngine`：含 `maas.aliyuncs.com` 或 `compatible-mode`
   的 URL 优先返回 `openAiEngine`；真正的 `dashscope.aliyuncs.com` 仍走 `dashScopeEngine`
   （满足「DashScope 不走 OpenAI 协议」需求）。
2. `SpeechModelSelector.java` `resolveModelName`：TTS 场景下若模型名明显是 ASR 模型
   （`asr/paraformer/sensevoice/whisper/fun-asr/gummy`，排除 `tts/cosyvoice/sambert/speech`）
   则防御性回落到端点默认 TTS 模型。新增 `isAsrModelName()` 辅助方法。

### 注意（非本次改动，按用户要求未处理）
- `src/main/java/com/oilquiz/app/ai/usage/db/entity/` 下
  `ApiPriceConfig.java`(L15) / `ApiRequestSchema.java`(L12) / `ApiResponseSchema.java`(L11)
  的 `@Entity` 用了 `@UniqueConstraint` 但缺 `import androidx.room.UniqueConstraint;`，
  Room 注解处理器报「找不到符号 UniqueConstraint」，卡住整体编译。
  该错误由其他工具（Qoder 等）改动引入，不在语音改动范围内，用户自行处理。
