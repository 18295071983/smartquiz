## 问题分析

### 1. 上下文兼容性问题
- Agent 模式使用 `UnifiedAgentEngine` 的独立上下文，与普通聊天的 `chatSend` 上下文不兼容
- 切换模式时上下文可能被重建，导致崩溃
- Agent 模式的工具调用结果会占用大量上下文空间

### 2. callback=null 问题
- `AgentChatHandler` 的 callback 在 `shutdown()` 时被设为 null
- 如果 Activity 被销毁重建，旧的 callback 变成孤立引用
- `UnifiedAgentEngine.destroy()` 也会设置 callback = null

### 3. 布局问题
- Agent 模式的工具调用和步骤显示使用独立布局，与其他模式不统一
- 没有模式切换动画
- 工具调用结果显示不完整（缺少执行时间、重试次数等）

### 4. 执行层面问题
- Agent 模式的流式推理与普通聊天的流式推理不统一
- 工具调用结果丢失执行时间信息
- 没有统一的进度展示

### Step 2: 修改 UnifiedAgentEngine 使用共享上下文

修改 `sendAndProcessWithLocalModel()` 方法：
- 使用 `aiService.chatSend()` 而不是独立的上下文
- 工具调用结果追加到消息中而不是重建上下文
- 添加上下文空间检查，避免溢出

### Step 3: 修复 callback=null 问题

在 `AgentChatHandler.java` 添加：
```java
private volatile boolean isShutdown = false;

public boolean isValid() {
    return !isShutdown && callback != null;
}

// 在所有 callback 调用前检查
private void safeCallback(Consumer<AgentChatCallback> action) {
    if (isValid()) {
        try {
            action.accept(callback);
        } catch (Exception e) {
            AILogger.e(TAG, "Callback error: " + e.getMessage());
        }
    }
}
```

### Step 4: 添加模式切换动画

在 `AIChatActivity.java` 添加：

    messageList.animate()

        .withEndAction(() -> {
            // 切换模式
            ChatModeManager.getInstance(this).setManualMode(ChatMode.AGENT);
            updateModeButtonText();

                .setDuration(150)

        .start();
