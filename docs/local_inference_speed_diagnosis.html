代码审查 2026-09-23 · 五阶段链路 × 每阶段慢的信号 × 判定表
总判断：代码已内置 GPU 全量层、FA C8、KV 增量、batch 512 等优化。真机上"慢"不是整体没优化，而是某个环节没吃到优化——最可疑的三个降级点：① 可用内存不足 → CPU-only/层数被砍（代码注释实测 8~11 t/s 或更慢）；② KV 每轮 FULL 全量重算（首字随历史线性变久）；③ FA C8 未触发（长序列 decode ≈1s/tok 级）。

慢信号：历史越长首字越久；工具 JSON/环境块每轮变化 → KV 前缀失配。

慢信号：FA 未触发 ≈1s/tok；层数不足 → CPU-GPU 交替实测 8~11 t/s。

5 · 流式回 UI
JNI token → Java → 渲染
因子：逐 token JNI 回调、UI 渲染。
通常不是瓶颈；仅当 token 已到但界面卡才查此段。
已知自动降级分支（4B 级模型 >1800MB，AIService 初始化时按可用内存执行）： 可用内存 <3200MB → 强制 CPU-only + 上下文≤6144（注释明示"慢但正常"）；<2500MB → GPU 层数限 30；<1500MB → 限 22；<800MB → 限 14。 层数不足时每 token 在 CPU/GPU 间交替，代码实测仅 8~11 t/s。
