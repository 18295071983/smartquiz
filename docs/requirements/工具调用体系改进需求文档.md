# 工具调用体系改进需求文档

| 项目 | 说明 |
| --- | --- |
| 文档版本 | v1.0 |
| 日期 | 2026年9月11日 |
| 提出方 | AI 助手（基于实际工具调用中的痛点反馈整理） |
| 适用范围 | App「AI 对话」模块的 Function Calling 工具体系（工具注册表、参数 schema、返回值规范、错误处理、权限联动等） |

---

## 一、背景

AI 助手以「完整 Agent 接管模式」运行，通过原生 Function Calling 自主规划并调用工具完成任务，可多轮、可组合、可并行。工具数量已达 100+，覆盖天气、油价、搜索、文件、数据库、UI 生成、媒体、计算等众多领域。

工具越多，**「选哪个、怎么填、结果长啥样、错了怎么办」** 四个环节的不确定性就越高。本文档系统梳理工具调用环节的核心痛点，并给出可落地的改进方案与优先级建议。

## 二、现状概述

当前工具体系具备以下特点：

1. **数量多、覆盖广**：100+ 工具，跨多个业务域；
2. **发现机制**：通过 tool_registry 提供 list / search / get 能力；
3. **调用方式**：原生 Function Calling，支持并行与组合；
4. **权限模型**：部分工具依赖系统权限，需与 permission_manager 配合。

在「开发体验」与「调用确定性」上，主要痛点集中在：**命名与选型、参数一致性、返回与错误规范、编排可预期性、权限联动**。

## 三、改进需求清单

### P0 高优先级（投入小、收益大，建议优先实施）

#### P0-1 工具命名与元数据规范化
- **现状问题**：工具数量多、命名相似（如 oil_price_query / oil_panorama / international_oil_price），仅凭名称难以判断适用场景，容易选错，需反复用 tool_registry 现查。
- **改进方案**：
  - 工具名尽量反映「动作 + 对象」，减少易混淆命名；
  - 为工具补充分类标签（category）与一句话适用场景（when_to_use）；
  - 对高度同义的工具进行合并或明确边界说明。
- **验收标准**：同类工具可直接区分用途；选型无需反复查表。

#### P0-2 参数 schema 统一与调用前校验
- **现状问题**：同义参数命名不统一（query / keyword、limit / num_results / maxResults）；互斥参数（city vs lat/lon）缺少显式约束，易都传或都不传；参数错误时提示不明确。
- **改进方案**：
  - 统一同义参数命名，保留别名兼容；
  - 对互斥/依赖参数做显式约束标注（二选一、成对出现）；
  - 调用前执行参数校验，错误信息指出具体字段与原因。
- **验收标准**：参数命名一致；互斥参数不满足时给出明确提示。

#### P0-3 返回值结构统一
- **现状问题**：返回格式不统一，有的返回对象、有的返回转义字符串 JSON 需二次解析，增加处理成本与出错概率。
- **改进方案**：
  - 统一返回结构，如 `{ success, data, error, meta }`；
  - 统一使用结构化对象，避免双重转义字符串。
- **验收标准**：所有工具返回结构一致，无需二次解析。

### P1 中优先级

#### P1-1 错误处理规范统一
- **现状问题**：错误形态五花八门——有的返回 error 字段、有的抛异常文本、有的静默空返回，难以统一兜底与重试判断。
- **改进方案**：统一错误码与错误字段；标注错误是否可重试（retryable）；避免静默失败。
- **验收标准**：错误可被统一识别与处理；可重试性明确。

#### P1-2 工具选型指引 / 智能推荐
- **现状问题**：工具多、边界模糊，选型依赖经验，易走弯路。
- **改进方案**：提供按意图推荐工具的能力（如根据用户诉求直接推荐最合适的工具与参数模板）。
- **验收标准**：常见意图有明确推荐工具。

#### P1-3 权限与调用联动
- **现状问题**：权限请求与工具调用分离，需先请求权限再调用，顺序遗漏会导致失败。
- **改进方案**：工具声明所需权限（permission 字段），调用前可自动提示/触发权限请求。
- **验收标准**：缺权限时可自动提示并引导授权。

### P2 低优先级（体验优化）

#### P2-1 耗时预估与并行提示
- **现状问题**：工具耗时差异大，能否并行、失败能否重试无标注，编排效率低。
- **改进方案**：标注工具耗时等级、是否可并行、失败重试策略。
- **验收标准**：可据此优化调用编排。

#### P2-2 大结果分页 / 截断提示
- **现状问题**：返回内容超长时无截断提示，易误判数据完整性。
- **改进方案**：返回 meta 中标注是否截断、总条数与分页信息。
- **验收标准**：可明确知晓结果是否完整。

#### P2-3 工具说明与示例完善
- **现状问题**：部分工具描述简略，缺少参数示例与返回示例。
- **改进方案**：补充参数示例、返回示例与常见用法。
- **验收标准**：常见工具可凭说明直接调用。

## 四、优先级与排期建议

| 阶段 | 内容 | 预期收益 |
| --- | --- | --- |
| 第一阶段 | P0-1 / P0-2 / P0-3 | 解决选错工具、填错参数、解析困难三大高频问题 |
| 第二阶段 | P1-1 ~ P1-3 | 提升容错性与调用效率 |
| 第三阶段 | P2-1 ~ P2-3 | 完善可预期性与文档完备度 |

## 五、验收标准汇总

1. 同类工具可直接区分用途，选型无需反复查表；
2. 参数命名统一，互斥/依赖参数有显式约束与提示；
3. 所有工具返回结构一致，无需二次解析；
4. 错误形态统一、可识别、可重试性明确；
5. 常见意图有明确的推荐工具；
6. 缺权限时可自动提示并引导授权；
7. 工具标注耗时等级与并行能力；
8. 大结果有截断/分页提示；
9. 工具说明含参数与返回示例。

## 六、范围与备注

- 本文档基于 AI 助手实际调用反馈整理，侧重「调用确定性」与「编排效率」。
- 命名规范化与返回值统一需评估对存量工具及调用的兼容影响。
- 具体技术实现方案由研发团队评估确定。
- 建议与《UI 组件系统改进需求文档》配套实施，两者共同构成「AI 能力层」的改进路线。
