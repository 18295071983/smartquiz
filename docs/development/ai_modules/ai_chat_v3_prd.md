# AI助手界面 v3.0 产品需求文档 (PRD)

> 版本: 3.0 | 更新日期: 2026-07-18 | 迭代目标: 深度思考、创意写作引擎修复 + ChatAdapter全面功能实现

---

## 1. 背景与目标

### 1.1 背景分析

当前AI助手界面存在以下问题：

| 问题分类 | 具体问题 | 影响 |
|---------|---------|------|
| **引擎功能** | DeepThinkingEngine深度思考引擎未完整集成到聊天流程 | 用户无法体验深度思考能力 |
| **引擎功能** | CreativeWritingEngine创意写作引擎与聊天模式切换脱节 | 创作功能不可用 |
| **UI显示** | ChatAdapter在流式生成时与Compose布局存在兼容性问题 | 消息闪烁、布局错乱 |
| **模式切换** | 四种聊天模式（普通、深度思考、Agent、创作）无法正确跟随切换 | 用户体验差，功能不可用 |
| **推理状态** | 推理状态显示不完整，AI服务信息展示缺失 | 用户无法了解当前推理进度 |
| **附件处理** | 消息附件无专用渲染器，显示方式与操作逻辑不完整 | 无法有效处理图片、文档等附件 |
| **消息队列** | 消息生成队列机制不完善，缺少唯一ID管道式流式生成 | 多消息并发处理混乱 |

### 1.2 迭代目标

#### 核心目标
- **修复深度思考引擎**：确保DeepThinkingEngine可用，完整展示思考过程
- **修复创意写作引擎**：确保CreativeWritingEngine可用，完整实现创作流程
- **实现ChatAdapter全面功能**：修复布局冲突，实现所有设计的功能
- **实现管道式流式生成**：消息队列、唯一ID、广播机制

#### 业务目标
- 用户可选择四种聊天模式并正常工作
- 深度思考过程可视化，用户可追踪推理过程
- 创意写作支持多阶段创作（大纲→分段→润色）
- 附件显示友好，支持图片、文档预览
- 流式生成平滑，无布局闪烁

### 1.3 非目标（本次不做）

- 不实现新的LLM模型集成
- 不改变现有的AIService核心推理逻辑
- 不重构整个聊天UI框架（仅修复和增强）

## 3. 功能需求

### 3.1 深度思考引擎 (DeepThinkingEngine)

#### 3.1.1 功能概述
深度思考引擎是一个模拟人类逐步推理过程的AI增强引擎，通过多步骤思考链来处理复杂问题。

#### 3.1.2 思考流程

| 阶段 | 描述 | 产出 |
|------|------|------|
| **理解问题** | 分析用户问题，识别关键信息 | 问题摘要 |
| **问题分解** | 将复杂问题拆解为可管理的子问题 | 子问题列表 |
| **知识检索** | 激活相关知识库和领域经验 | 知识关联 |
| **假设评估** | 评估多个解决方案的可行性 | 候选方案排序 |
| **逻辑推理** | 进行多层逻辑推导 | 推理链 |
| **验证答案** | 检查解决方案的正确性和完整性 | 验证报告 |
| **综合答案** | 整合所有推理结果，生成最终输出 | 最终答案 |

#### 3.1.3 与聊天集成点

```
用户消息 → 模式判断 → 深度思考模式 → DeepThinkingEngine
    ↓
    ├─ 开始思考 (startThinking)
    ├─ 问题分解 (analyzeProblemDecomposition)
    ├─ 知识检索 (gatherKnowledge)
    ├─ 假设评估 (evaluateHypotheses)
    ├─ 逻辑推理 (logicalReasoning)
    ├─ 验证答案 (verifySolution)
    └─ 综合答案 (synthesizeAnswer)
    ↓
聊天界面展示思考过程 → 最终答案
```

#### 3.1.4 UI展示要求

- 思考过程以折叠/可展开的方式展示
- 每个思考步骤有进度指示器
- 显示当前置信度和推理深度
- 思考过程结束后自动展开最终答案

### 3.2 创意写作引擎 (CreativeWritingEngine)

#### 3.2.1 功能概述
创意写作引擎是一个专门用于创作任务的AI增强引擎，支持多阶段、结构化的内容创作。

#### 3.2.2 创作流程

| 阶段 | 描述 | 产出 |
|------|------|------|
| **主题提取** | 从用户输入中识别创作主题和类型 | 主题信息 |
| **大纲生成** | 根据主题生成结构化大纲 | 3-6个部分的大纲 |
| **分段撰写** | 按大纲逐段生成内容 | 各部分内容 |
| **润色总结** | 对全文进行润色和总结 | 最终作品 |

#### 3.2.3 支持的创作类型

| 类型 | 触发关键词 | 特点 |
|------|-----------|------|
| **故事/小说** | 写故事、创作小说、编个故事 | 有角色、情节、冲突 |
| **诗歌** | 写一首诗、作诗 | 韵律、意象 |
| **散文** | 写一篇散文 | 形散神聚 |
| **邮件** | 写一封邮件、帮我写邮件 | 正式、格式正确 |
| **演讲稿** | 写一篇演讲稿 | 口语化、有感染力 |
| **广告语** | 写一句广告语、帮我想个口号 | 简洁、有冲击力 |

#### 3.2.4 与聊天集成点

```
用户消息 → 模式判断 → 创意写作模式 → CreativeWritingEngine
    ↓
    ├─ 主题识别 (extractTheme)
    ├─ 大纲生成 (generateOutline)
    ├─ 分段撰写 (逐个section调用AI)
    └─ 内容整合
    ↓
聊天界面展示创作进度 → 最终作品
```

#### 3.3.2 流式生成优化

**当前问题**：
- notifyItemChanged在Compose中可能导致重绘闪烁
- 没有使用DiffUtil进行高效更新
- 消息内容更新与Compose布局生命周期冲突

**解决方案**：
- 使用Payload机制进行局部更新
- 实现DiffUtil.ItemCallback
- 确保在主线程执行UI更新
- 添加防抖机制，避免频繁更新

#### 3.3.3 推理状态智能显示

**状态信息**：
- 推理阶段（InferencePhase）
- Token统计（已生成/总计）
- 生成速度（tokens/second）
- GPU/CPU使用状态
- 模型信息

**UI组件**：
```
┌─────────────────────────────────────────┐
│ ⚙️ 正在初始化...                         │  ← 阶段图标和文字
│ ──●───────────────────────────────────  │  ← 进度条
│ 已生成: 25 token · 速度: 12.5 t/s        │  ← 统计信息
│ GPU: 71层 · 内存: 4.2GB                 │  ← 资源使用
└─────────────────────────────────────────┘
```

### 3.5 消息生成队列与管道式流式生成

#### 3.5.1 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                    消息生成队列系统                           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  用户输入 ──► [MessageQueue] ──► [Pipeline] ──► UI更新       │
│                                                              │
│  Pipeline架构：                                               │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐         │
│  │ 输入队列 │──►│ 处理队列 │──►│ 输出队列 │──►│ 广播器  │         │
│  │ (FIFO)  │  │ (FIFO)  │  │ (FIFO)  │  │         │         │
│  └─────────┘  └─────────┘  └─────────┘  └────┬────┘         │
│                                              │               │
│                              ┌───────────────┼───────────┐   │
│                              ▼               ▼           ▼   │
│                          [Adapter]    [Logger]     [Stats]  │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

#### 3.5.2 唯一ID机制

**ID格式**：
```
msg_{timestamp}_{random}_{sequence}

示例：msg_1716200000000_a1b2c3_001
```

**ID作用**：
- 消息唯一标识
- 流式更新路由
- 生成状态追踪
- 取消/重试操作

#### 3.5.3 流式生成广播器

**功能**：
- 多订阅者模式（Adapter、Logger、Stats等）
- 按消息ID路由更新
- 支持部分更新（token增量、状态变更）
- 线程安全

**广播事件类型**：

| 事件类型 | 描述 | 数据 |
|---------|------|------|
| MESSAGE_CREATED | 消息创建 | messageId, initialContent |
| TOKEN_APPENDED | Token追加 | messageId, token, position |
| STATUS_CHANGED | 状态变更 | messageId, newStatus |
| THINKING_UPDATE | 思考更新 | messageId, thinkingStep |
| ATTACHMENT_UPDATE | 附件更新 | messageId, attachments |
| MESSAGE_COMPLETED | 消息完成 | messageId, finalContent, stats |
| MESSAGE_FAILED | 消息失败 | messageId, error |
| MESSAGE_CANCELLED | 消息取消 | messageId |

### 3.6 模式切换

#### 3.6.1 模式类型

| 模式 | ID | 触发条件 | 特点 |
|------|----|---------|------|
| **普通** | normal | 默认 | 直接回答，简洁高效 |
| **深度思考** | deep | 分析类问题、手动选择 | 多步骤推理，过程可视化 |
| **Agent** | agent | 任务型请求、手动选择 | 工具调用，多步骤执行 |
| **创意写作** | creative | 创作类请求、手动选择 | 结构化创作，大纲→分段 |

#### 3.6.2 切换机制

**自动切换**：
- 根据用户消息内容自动识别
- ChatModeManager.determineMode()

**手动切换**：
- 模式选择器UI
- 立即生效（非生成中）或延迟生效（生成中）

**生成中切换**：
```
用户请求切换模式
    ↓
检测是否正在生成
    ├─ 未生成中 → 立即切换，重建上下文
    └─ 生成中 → 记录pendingMode，提示"当前生成完成后切换"
            → 当前生成完成后自动切换
```

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 消息列表滚动帧率 | ≥60fps |
| 流式更新间隔 | 50-200ms（可配置） |

- Android 12+ (API 31+)
- 支持竖屏和横屏
- 支持不同屏幕尺寸（手机、平板）
- 深色/浅色主题

### 4.4 可维护性要求

- 代码模块化，各引擎独立
- 完善的日志记录
- 可配置的参数（如流式更新间隔、缓存大小）
- 单元测试覆盖率 ≥60%
