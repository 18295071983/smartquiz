# 智能题库应用重构设计文档

> **文档版本**：v2.0（2026-08-28 依据 git 提交记录与实际代码结构修订）
> **历史版本**：v1.0（2026-05-16 项目初始化时的重构计划）
> **说明**：v1.0 为重构前的规划文档；v2.0 按实际落地情况修订，并补充重构完成后的架构演进历程。

## 1. 重构目标

根据开发文档的规范，对智能题库应用进行重构，确保代码结构符合标准，提高代码质量、可维护性和可扩展性。

**重构结果**：目录结构重构、ViewModel 层扩展、工具类分类已基本落地；在此基础上，应用从"题库工具"演进为"AI 驱动的学习助手"（AI Chat v2/v3、Agent 体系、语音、多模态、动态布局画布等）。

### 3.4 AI功能技术实现（v2.0 修订）

#### 3.4.1 技术选型（当前实际）
- **本地推理引擎**：llama.cpp（JNI 封装 `src/main/cpp/llama-bridge.cpp`），GGUF 量化模型 + mmap，Vulkan 后端默认开启
- **模型选择**：GGUF 量化模型（Qwen 系列，支持 0.5B～数 B 级别，可下载切换）
- **在线推理**：OpenAI 兼容 API（chatJson / generateStreamIncremental 统一 JSON 协议，v1.11），本地/在线混合路由 + 本地降级
- **多模态**：TFLite（CV）+ MLKit（OCR）+ 附件解析整合（2026-08-10 架构 v2.3）
- **语音**：在线 ASR（/audio/transcriptions）、TTS（/audio/speech、DashScope）+ 系统 TTS 兜底
- **AI 工具链**：OpenAI Tool Calling 协议 + 本地 Agent 原生 Function Calling 单循环架构，40+ 工具（数据库/文件/OCR/UI 控件/布局编辑等）
- **性能优化**：上下文窗口动态推断（GET /models）+ 动态压缩阈值（contextWindow×60%）+ is_partial 增量解析 + 流式渲染

#### 3.4.2 架构设计（当前实际：本地/在线混合 Agent 架构）
```
┌───────────────────────────────────────────────────────────┐
│                       应用层（UI）                        │
│   AIChatActivity（模块化拆分） / 天气横幅 / 动态布局画布   │
├───────────────────────────────────────────────────────────┤
│                   Agent 层（本地/在线路由）                │
│  ┌──────────────────┐    ┌──────────────────────────┐    │
│  │ 本地 Agent        │    │ 在线 Agent                │    │
│  │ (Function Calling │    │ (OnlineAgentEngine +      │    │
│  │  单循环架构)      │    │  工具链/记忆/思考链)      │    │
│  └──────────────────┘    └──────────────────────────┘    │
├───────────────────────────────────────────────────────────┤
│                    AI 服务层                              │
│  模型管理 │ 推理调度 │ 工具注册(AIToolManager) │ 语音服务  │
├───────────────────────────────────────────────────────────┤

```

#### 3.4.3 核心组件（v2.0 修订）
- **模型侧**：ModelManager（模型下载/验证/缓存）、本地推理 JNI 桥、在线模型客户端（统一 JSON 协议）
- **Agent 侧**：OnlineAgentEngine（在线 Agent 引擎）、本地 Function Calling 单循环引擎、AIToolManager（40+ 工具注册与调度）、AgentMemoryStore（Agent 记忆）
- **对话侧**：ai/chat/ 各子包（流式渲染、原生 UI 组件卡片、Markdown/Mermaid/KaTeX 渲染、历史管理）
- **语音侧**：SpeechManager（门面）+ ASR/TTS 引擎策略（OpenAI 兼容 / DashScope / 系统 TTS）
- **功能侧**：QuestionGenerator（题目生成）、QuestionAnalyzer（题目解析）、LearningAssistant（学习辅助）、Translator（翻译）

## 4. 重构步骤

### 4.1 准备阶段

1. **代码审查**：对现有代码进行全面审查，识别需要重构的部分
2. **测试准备**：创建测试环境，准备测试数据
3. **备份代码**：在重构前备份所有代码，确保可以回滚

### 4.2 目录结构重构

1. **创建缺失目录**：
   - `viewModel` 下创建各模块的 ViewModel 目录
   - `util` 下创建分类子目录
   - `service` 下创建分类子目录

2. **移动文件**：
   - 将工具类移动到对应的分类目录
   - 将服务移动到对应的分类目录

3. **更新包路径**：
   - 更新移动文件的包路径
   - 更新所有引用这些文件的导入语句

### 4.3 代码规范重构

1. **命名规范**：
   - 检查并修改不符合规范的类名、方法名、变量名

2. **注释规范**：
   - 为所有类和方法添加Javadoc注释
   - 为复杂逻辑添加行内注释

3. **代码风格**：
   - 统一代码缩进和格式
   - 优化空行使用

4. **异常处理**：
   - 优化异常捕获和处理
   - 添加适当的日志记录

### 4.4 功能模块重构

1. **ViewModel 层**：
   - 创建各模块的 ViewModel
   - 实现业务逻辑处理

2. **Repository 层**：
   - 优化数据访问逻辑
   - 实现数据缓存

3. **Service 层**：
   - 优化服务实现
   - 添加服务接口

4. **UI 层**：
   - 优化界面设计
   - 实现响应式布局

### 4.5 测试阶段

1. **单元测试**：
   - 为核心功能编写单元测试
   - 确保测试覆盖率达到80%以上

2. **集成测试**：
   - 测试模块之间的交互
   - 测试数据库操作和网络请求

3. **UI测试**：
   - 测试用户交互流程
   - 测试不同屏幕尺寸的适配

### 4.6 验证阶段

1. **功能验证**：
   - 验证所有功能是否正常工作
   - 验证重构后的代码是否符合预期

2. **性能验证**：
   - 测试应用的性能指标
   - 确保性能达到要求

3. **安全性验证**：
   - 验证应用的安全性
   - 确保数据安全和权限管理

### 6.1 潜在风险

1. **代码兼容性**：重构可能导致现有功能出现兼容性问题

3. **性能影响**：

4. **时间估算**：
