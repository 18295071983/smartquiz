## 一、总体结论

参数层（传参校验、必填项、报错提示）已修复，四个 action 不再直接失败。
剩余问题集中在一处根因 + 一个独立设计缺陷：

| 编号 | 根因 | 影响范围 | 优先级 |
|---|---|---|---|
| D-1 | HTML 转文本时未剔除 script / style / noscript / svg / iframe | 四个 action 全部字段 | P0 |
| D-2 | PC 版与移动版 DOM 未去重，同一段正文重复出现 | contentSlices、dates | P1 |
| D-3 | summary 字段实为"原始文本前 N 字符切片"，非生成摘要 | summarize、smart_read | P1 |
| D-4 | extract_info 的 query 参数完全未被使用 | extract_info | P1（或改名收口） |

### D-1 的证据（最关键）

IANA 极静态页调用 extract_info，返回：

    keywords = ["the","of","var","domains","example","as","are","domain","toc","return"]

其中 var / toc / return 全部来自页面内一段给目录做高亮的 JS。
同页 contentSlices 的 index 31/32/33 是完整 JS 源码：

    // Highlight the table-of-contents entry for the section currently at the
    // top of the viewport, following the page as it scrolls.
    (function () {
      var toc = document.querySelector('.article-toc');

广西税务局页同理，keywords 返回 if / var / function / searchword / == / nbsp / trim / return。

### D-1 的修复结论（可直接落地的验收标准）

结构解析器本身是合格的，**不需要重写**。IANA 页实测：
- headings 精确返回 ["H1: Example Domains", "H2: Further Reading"]，不多不少
- dates 精确抽到 2026-09-27
- phones 如实返回 []
- title / category 正确

同页正文段 index 13、14 与原文一字不差。
唯一问题是脚本未剔除。**只需在 HTML 转文本前过滤 script/style/noscript/svg/iframe 一类标签**，
即可同时修好 keywords、phones、headings、contentSlices、summary、content。

## 三、验收口径

修复后按以下顺序验证，全绿才算可用：

**P0（阻断级）**
1. R-13 四个页面的 keywords 不再出现 JS 语法词
2. R-08 / R-01 content 与 summary 不含 `function(`、`var `、`querySelector`、Sentry 相关串
3. R-02 summary 不含站点模板导航串

**P1（质量级）**
4. R-17 / R-18 正文与日期去重
5. R-05 conciseSummary 能概括内容、keyPoints 为实质要点
6. R-14 / R-15 / R-16 空标题、假号码、非法日期归零

**P2（设计收口）**
7. R-10~R-12：query 要么真正生效，要么把 action 改名为 extract_meta 并更新文档
8. R-09：limit 对 search_and_read 是否应生效，明确语义

## 四、建议的最小改动

1. 在 HTML 转文本前，剔除 `script` / `style` / `noscript` / `svg` / `iframe` 节点（一处改动，覆盖上文绝大多数 FAIL）
2. contentSlices 输出前按正文文本指纹去重（hash 前 200 字即可）
3. summary 字段二选一：接真实摘要生成，或改名为 excerpt 并如实描述为"正文前 N 字"
4. extract_info：query 接语义抽取，或改名收口

## 六、真机复测记录

### 2026-11-02 第一轮（剥脚本修复后）

失败项 **13 → 3**，且 3 条同一个原因（`query`）。已验证：
- IANA 页 keywords 里的 JS 语法词消失、`contentSlices` 不再有整段 JS；
- 税务局页的模板导航串不再占据摘要开头，摘要可直接使用；
- PC/移动两套 DOM 的重复正文已去重；
- `summarize` / `smart_read` / `search_and_read` / `extract_info` 同时恢复正常。

新暴露的三个细节：`queryMatches` 恒为 `[]`、关键词被小数/百分号切断（"5万元"）、
`&emsp;` 未解码、英文摘要句边界被拼成残句。

### 2026-11-02 第二轮（本轮修复）

| 问题 | 处理 |
|---|---|
| `queryMatches` 恒为 `[]` | 命中判定从"整词包含"放宽为：整词 2 分 + 两字片段 1 分，累计 ≥2 分 |
| 关键词 "5万元"/"04万元" | 分词只按"非中文、非字母"切分，数字直接丢弃；补英文停用词 |
| `&emsp;` / `&copy;` / `&times;` | 命名实体查表 + 十进制/十六进制数字实体解码 |
| "…maintained。applications." | 摘要改为挑**连续**最多 3 句（窗口打分），英文句间用 ". " 连接 |
| R-09 `limit` 语义 | 定死为：`limit` = 搜索条数，同时是默认读取条数上限（≤3）；要单条用 `detailIndex` |

状态：单测 185 个类 / 1336 条全绿，APK 已装回设备。**P0/P1 仍需按第三节在真机上再跑一遍确认。**

### 2026-11-02 第三轮（query / 实体 / 分词 / 句边界修复后）

**22 条：17 通过 / 4 待修 / 1 存疑。** 已验证：`queryMatches` 在中文页生效（税务局 2 条、汽车之家 5 条命中）。

四条待修里三条同源：**行内硬换行没有折叠**（英文站每 ~70 字符一个 `\n`，被当成句子边界）——
表现为英文摘要首句丢失、句子截断在 "…support production."、`queryMatches` 只给半句；
中文页因段落是连续长行而看不出问题。其余两条是 `queryMatches` 打分/去重、
关键词虚词残渣（"日至"/"日期间"）、日期格式混排。

| 问题 | 处理 |
|---|---|
| 行内硬换行被当成句边界 | 块级标签连闭合标签一起换行；连续换行=段落、单个换行=空格 |
| 英文 query 命中噪音 | 英文只认整词（两侧非字母数字），中文保留片段加分但单句最多 2 分；结果按指纹去重 |
| 日期 `2026年1月1日` / `2026-05-27` 混排、带空格的抓不到 | 允许字间空格，统一归一成 `yyyy-MM-dd` 并去重 |
| 关键词 "日至"/"日期间" | 按日期/序数虚词修剪词头词尾 + 连接词黑名单 |

状态：单测 185 个类 / 1340 条全绿，APK 已装回设备；待真机第四轮确认。

**存疑未动**：栏目索引页（`col/col`、纯列表页）在 `search` 排序里天然靠前，
建议按 URL 特征降权 —— 属排序口径，需单独确认，不在本清单的"修复"范围。

### 2026-11-02 第四轮：换掉抽取架构（不再靠正则补丁）

用户反馈："你刚刚改的都是固定的网页，不正规啊，你看看业界是怎么做的"。成立：前几轮是给
`network_search` 的正则抽取逐条打补丁，而项目里已有正规实现（`WebPageReaderTool`：Jsoup DOM +
语义标签 + 文本密度 + 链接密度），只是 `network_search` 没走它。

- 抽出 **`HtmlContentExtractor`** 作为唯一实现：解析 → 去噪 → 语义标签（含"像不像正文"校验）→
  密度评分 → 父容器提升 → 空容器兜底 → 按块级元素出段落。两个工具共用。
- 删掉 `NetworkSearchTool` 的正则抽取器（title/meta/headings/links/slice/stripNoise 等一批方法与常量）。
- 修 **GBK 解码**：OkHttp 默认按 UTF-8，people.com.cn 这类站整页乱码；改为
  响应头 → meta → 严格 UTF-8 → GB18030 兜底。
- 切片门槛 50 → 20 字（新闻单段常 30~40 字，50 会把整篇切空）。
- 新增 `LiveExtractionProbeTest`：`LIVE_NET=true` 时联网抓真页、走同一条管线做卫生断言。

真页结果（IANA 781 字 / RFC7000 字 / people 首页 6839 字 / sina 首页 12706 字 /
chinanews 正文页 4273 字、58 段）。另确认：people、sina 的**正文页是 JS 渲染**，
本地只能拿到壳（200~600 字），这类页面归 `read_url`（服务端渲染），不是本地抽取器该背的锅。
