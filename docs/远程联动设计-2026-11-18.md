# 手机 ⇄ 电脑插件 双向联动设计（2026-11-18）

> 目标：插件连上以后，手机端不再只是"被动接收电脑数据、覆盖到手机对话里"。
> 手机上的 AI（agent）可以通过对话主动调用电脑插件做联动；电脑端也能下发**调试指令**到手机执行并回传。
>
> 现状：`remote_dsh` 已经能"手机 AI 让电脑跑任务"，但——
> - 电脑 → 手机只有 `phone_ui`（slot/toast/notification）+ `ui_component` 卡片 + 命令队列里少数白名单（toast/dialog/notification/reminder）；
> - 手机端把远程会话事件**当成自己的会话渲染**（`ChatRemoteMode.isActive` 时外壳切远程、事件覆盖当前对话），所以看起来"只能被动接收"；
> - 手机 AI 没有一个"面向电脑插件"的通用工具（只有 `remote_dsh` 的粗粒度 `run`）。

---

## 1. 总体思路：一条链路，两种模式

同一条 WS 链路（`/ws/events` + `/ws/ui` + `/v2/action`），区分两种使用模式：

| 模式 | 手机对话 | 数据方向 | 用途 |
|---|---|---|---|
| **镜像模式**（现有） | 显示电脑会话 | 电脑 → 手机（event 全量） | 手机当电脑的第二块屏 |
| **联动模式**（新增，默认） | **保留手机本地对话** | 双向、按需 | 手机 AI 主动问电脑 / 让电脑干活；电脑把结果作为"外部卡片"插进手机对话 |

联动模式的关键约束：**电脑数据绝不覆盖手机对话**——一律以独立 part 呈现（工具卡 / 系统消息 / 远程任务卡），并带 `origin: "pc-link"` 标记，可折叠、可清空。

---

## 2. 协议：在 `/v2/action` 上加"联动 RPC"

复用现有 `POST /v2/action`（已鉴权 + caps 白名单），新增动作；WS `/ws/events` 回传流式片段。

### 2.1 请求（手机 → 电脑）

| action | 参数 | 返回 | 说明 |
|---|---|---|---|
| `agent.ask` | `prompt`、`session_id?`、`link_id`、`stream=true` | `{ok, link_id, accepted}` | 交给电脑 DSH agent 处理；结果用 WS 流式回 |
| `agent.cancel` | `link_id` | `{ok}` | 取消一次联动请求 |
| `agent.status` | `link_id` | `{state: queued|running|done|failed, ...}` | 查询状态（断线重连后补状态） |
| `pc.sessions` | `limit` | `{sessions:[{id,title,updated_at}]}` | 列电脑会话（只读） |
| `pc.read_file` | `path`、`max_bytes` | `{name,size,sha256,text}` | 读电脑文件（沿用 `/ws/file` 的大小/白名单限制） |
| `pc.exec_tool` | `tool`、`args`（白名单） | `{ok, result}` | 让电脑执行一个**白名单工具**（默认只读：status/sessions/read_file） |

### 2.2 回传（电脑 → 手机，WS `/ws/events`）

| type | 字段 | 说明 |
|---|---|---|
| `link.started` | `link_id, session_id?` | 已受理 |
| `link.delta` | `link_id, text` | 流式增量（电脑 agent 的输出片段） |
| `link.tool` | `link_id, tool, args, state` | 电脑执行了某工具（手机端渲染成子步骤） |
| `link.done` | `link_id, text, usage` | 完成（最终文本） |
| `link.error` | `link_id, code, message` | 失败/取消 |

手机端按 `link_id` 聚合成**一条**"电脑 · 联动任务"卡片，不写进本地消息的正文。

### 2.3 调试指令（电脑 → 手机，扩展现有 cmdQueue）

现有 `cmdQueue` 白名单是 `ui_component/toast/dialog/notification/reminder`。新增 `debug.*`：

| tool | 参数 | 回传 |
|---|---|---|
| `debug.logcat` | `lines`、`filter` | `{text}` |
| `debug.screenshot` | `quality` | `/ws/file` 推一张图（file_begin/chunk/end） |
| `debug.view_tree` | `max_depth` | `{tree}`（当前前台 Activity 的 View 层级摘要） |
| `debug.exec_tool` | `tool`、`args` | `{ok,result}`（**必须在手机端弹确认**） |

手机端执行器：`RemoteCmdWorker`（新类）轮询 `/v2/cmd`，按 tool 分派，执行完 `POST /v2/cmd_ack`。危险指令一律 `needs_confirm`，由通知/弹窗确认后才执行。

### 2.4 手机能力导出（把手机 agent 的工具交给电脑）

目标：电脑端能**发现并调用手机侧的工具**，用来远程测试手机 agent 与工具系统；反向也让手机 agent 的能力变成 DSH 客户端可编排的能力。

**手机 → 电脑（连接时注册能力目录）**

```jsonc
// WS /ws/ui 或 POST /v2/phone/register（带设备令牌）
{ "type": "phone.catalog", "rev": 3, "tools": [
  { "name": "ui_component", "desc": "创建原生 UI 组件", "level": "exec",
    "params": { "type": "object", "properties": { "action": {"type":"string"} } } },
  { "name": "file_reader",  "desc": "读手机文件", "level": "read" }
] }
```

- 只上报**工具名/描述/参数 schema/风险级**，不上报实现；
- `level`：`read`（默认允许远程调）/ `exec`（需白名单 + 手机确认）/ `blocked`（不上报）。

**电脑 → 手机（调用）**

| action | 参数 | 返回 |
|---|---|---|
| `phone.tools.list` | — | `{rev, tools:[...]}` |
| `phone.tools.invoke` | `name`、`args`、`req_id`、`confirm_token?` | `{ok, req_id, accepted}`；结果用 `tool.result` 帧回 |
| `tool.result`（手机→电脑） | `req_id`、`ok`、`result`、`elapsed_ms`、`error?` | 与 `phone.tools.invoke` 配对 |

- PC 插件暴露给 DSH 客户端的工具：`phone_tools`（`list` / `invoke`），让电脑的 agent 也能"调手机的工具"；
- `exec` 级工具在手机上弹确认（复用 `RemoteCmdActionReceiver` 的通知按钮）；超时 30s 未确认 → `denied`；
- 目录变更（注册新工具/插件）时手机主动重推 `phone.catalog`（rev+1），PC 面板实时可见。

### 2.5 手机本地事件回传（给远端优化用）

手机把**本地 agent / 工具系统的事实**推给电脑，插件解析后既给 DSH 客户端看，也用于优化（例如"手机端某工具渲染失败"）。

| type | 字段 | 用途 |
|---|---|---|
| `phone.event.tool` | `name, args_digest, ok, elapsed_ms, error?` | 工具调用轨迹（不含敏感参数明文） |
| `phone.event.agent` | `state: idle|thinking|tool|done|error, round, tokens?` | agent 状态机 |
| `phone.event.ui` | `activity, screen_dp, theme, fps?` | 当前界面/尺寸/主题，供"屏幕显示优化" |
| `phone.event.error` | `where, message, stack_digest` | 崩溃/渲染失败回传 |

- 插件侧：`/v2/phone/events` 存最近 N 条（内存环形缓冲），`/v2/phone/events?since=` 给 DSH 客户端拉取；
- 默认只回传**结构化摘要**（digest/计数/枚举），不回传聊天正文、文件内容、剪贴板；
- 隐私开关：手机「远程连接」页提供"回传本地事件（诊断用）"，默认关闭。

### 2.6 屏幕镜像与操控（电脑操控手机）

在 2.3 的 `debug.screenshot` 之上做"持续帧 + 输入注入"：

| 帧/指令 | 方向 | 说明 |
|---|---|---|
| `screen.start` / `screen.stop` | 电脑 → 手机 | 开始/停止投屏；手机端 `MediaProjection` 或 `screencap` 限频 2–5 fps |
| `screen.frame` | 手机 → 电脑 | `{seq, ts, w, h, b64(jpeg)}`；大帧走 `/ws/screen` 独立通道，避免挤占事件流 |
| `screen.input` | 电脑 → 手机 | `{kind: tap|swipe|key|text, x,y,x2,y2,duration,keycode}` |

- **必须显式授权**：手机「远程连接」页新增"允许电脑操控屏幕"开关（默认关），开启时状态栏常驻提示；
- 只在 App 前台 + 已连接 + 授权未过期时生效；锁屏/切后台自动 `screen.stop`；
- PC 面板用 `<canvas>`/`<img>` 渲染帧，鼠标事件映射成 `screen.input`；支持点击/滑动/返回/Home/输入文字；
- 帧率、分辨率、带宽三档可调（`screen.config {fps, maxWidth, quality}`）。

**权限前提（必须先说清，否则做出来也跑不起来）**

| 能力 | 非 root 可行路径 | 限制 |
|---|---|---|
| 取屏 | `MediaProjection` + 前台服务（`mediaProjection` 类型） | 首次需用户点"开始投射"系统弹窗；锁屏/息屏会停 |
| 注入点击/滑动/返回 | `AccessibilityService`（用户到系统设置手动开启） | 需声明无障碍服务并在 App 内引导开启；部分 ROM 会杀后台 |
| 文字输入 | 无障碍 `ACTION_SET_TEXT`（聚焦输入框） | 非输入框场景只能走剪贴板粘贴 |
| 开发期兜底 | `adb shell input` / `screencap`（USB 调试） | 仅调试，不作为产品路径 |

因此电脑操控手机的产品形态应是：**引导用户开无障碍 + 每次投屏单独授权**，而不是静默获得控制权。

### 2.7 手机 CLI：一个统一命令面（推荐做法）

**要不要做"手机 CLI"？要，但不是装一个独立的手机命令行程序**，而是：

```
电脑（DSH agent / 终端）  →  插件  →  WS  →  手机 App 内置 PhoneCli 解释器
        phone_cli 工具            /v2/action cli.exec         解析 argv → 调本机能力
```

理由：
- 不用 root、不用 adb、不依赖 Termux；权限走 App 自己（无障碍 / MediaProjection / 通知）；
- 对 DSH 只暴露**一个工具** `phone_cli`，命令面稳定、可脚本化、可 `help` 自描述，比"每加一个能力就加一个 HTTP 路由"好维护；
- 电脑端再包一层 `dsh-phone` 本地 CLI（`node cli.mjs "ui dump"`），人/脚本/CI 都能用，DSH agent 走工具。

**协议**

| 帧 | 方向 | 内容 |
|---|---|---|
| `cli.exec` | 电脑 → 手机 | `{req_id, argv:"ui dump --max-depth 8", timeout_ms}` |
| `cli.stdout` / `cli.stderr` | 手机 → 电脑 | `{req_id, seq, text}`（分片流式，单条 ≤ 4KB） |
| `cli.exit` | 手机 → 电脑 | `{req_id, code, elapsed_ms}` |

> **P1 已落地（2026-11-18，只读子集）**：手机 `PhoneCli` + `RemoteCommandExecutor` 的 `cli` 分支 +
> 插件 `phone_cli` 工具 + `POST /v2/cli`。真机实测通过：`version`、`tools list`（64 个工具）、
> `ui dump --max-depth 2`（返回 `activity=... size=1220x2656` 的 View 树）。
> 事故记录：`execPhoneCli` 最初定义在 `if (!ctx.tools) {...} else {...}` 块里，而 `/v2/cli`
> 路由在模块顶层注册 → 调用时 `ReferenceError` 把插件进程带崩；已挪到模块作用域并给路由加
> try/catch（任何异常退化为 JSON 500，不再崩宿主）。

**命令集（P1 先做前两行，其余按需）**

| 命令 | 说明 | 风险级 |
|---|---|---|
| `help` / `version` | 自描述、版本 | read |
| `tools list` / `tools show <name>` | 手机工具目录与 schema | read |
| `tools call <name> <json>` | 远程调手机工具 | exec（手机确认） |
| `ui dump [--max-depth N] [--json]` | 当前前台 View 树摘要 | read |
| `ui find --text=... [--timeout]` | 按文字找控件（返回 bounds） | read |
| `ui wait --text=... --timeout=5s` | 等界面出现某文字 | read |
| `screen shot [--quality 60]` | 单帧截图（base64 → /ws/file） | read |
| `screen start/stop --fps --max-width` | 投屏开关 | exec |
| `input tap x y` / `input swipe ...` | 注入点击/滑动（无障碍） | exec（强确认） |
| `input key back|home|enter` / `input text "..."` | 按键/输入文字 | exec（强确认） |
| `agent ask "<prompt>" [--wait]` | 让手机 agent 处理一句话，流式回 | exec |
| `agent status` / `agent cancel` | 状态/取消 | read |
| `app list` / `app start <activity>` | 应用内页面跳转（白名单） | exec |
| `logcat [--lines 200] [--filter TAG]` | 脱敏日志 | read |
| `events [--since] [--limit]` | 本地事件（同 2.5） | read |
| `prefs get <key>` / `theme get` | 只读配置（敏感键拒绝） | read |

**输出约定**：默认纯文本（人读）；`--json` 输出 JSON（agent 解析）；退出码 `0/1/2`（成功/业务失败/参数错）；单次输出上限 256KB，超出截断并置 `truncated:true`；`exec` 级命令在手机上弹确认，拒绝返回 `code=3 denied`。

**安全**：

- 命令级白名单在手机端硬编码，插件端只能"转发"不能扩权；
- `input` / `app start` / `tools call` 必须**每次确认**（通知按钮或前台弹窗），确认窗口 30s；
- 同一设备 60s 内 `exec` 次数上限（默认 20），超限 `code=4 rate_limited`；
- 全部命令写手机本地审计（时间/命令/结果码，不含输出正文），可在「远程连接」页查看/清空；
- Release 包默认关闭 `input`/`app start`，需要用户在开发者选项里打开"允许远程调试"。

### 2.8 鉴权边界（2026-11-18 决定）

- **手机端**：独立登录 DeepSeek 账号（B 方案，PKCE + loopback + `x-dsh-auth-token`），token 只存手机；
- **电脑端**：保持 DSH 自己的账号鉴权，**不使用手机账号**，两边 token 不互通、不反向代理；
- 手机侧的「用电脑账号」（A 方案）只是手机的一种可选模式，与 B 并存，互不影响。

**电脑端 CLI（`dsh-phone`）**：

```
node tools/dsh-plugin-smartquiz-remote/cli.mjs --token <t> "ui dump"
dsh-phone "tools call file_reader {\"path\":\"Download/a.txt\"}"
```

同一套 `cli.exec` 协议，只是入口从 DSH 工具换成终端；DSH agent 用 `phone_cli` 工具、人用 `dsh-phone`，两条入口共用命令解析。

## 3. 手机端工具：`dsh_link`

注册到 `AIToolManager`（与 `remote_dsh` 并存，`remote_dsh` 保留给"镜像/粗粒度"场景）：

```
dsh_link(action)
  status        → 连接状态、电脑是否在线、当前 link 数
  ask(prompt)   → 发 agent.ask，阻塞收集 link.delta/link.done，返回最终文本 + 工具步骤
  sessions      → pc.sessions
  read_file     → pc.read_file（只读，大小上限沿用 32MB）
  debug(action, args) → debug.logcat / view_tree / screenshot
  cancel(link_id)
```

返回结构：`{text, steps:[{tool,args,state}], link_id, elapsed_ms}`，由手机 AI 再决定怎么回复用户。

**电脑端工具 `phone_tools`**（DSH 客户端可见，让电脑 agent 反向调手机）：

```
phone_tools(action)
  list                 → 手机上报的工具目录（name/desc/level/params）
  invoke(name, args)   → 发 phone.tools.invoke，等 tool.result；exec 级会先让手机确认
  events(since, limit) → 拉手机本地事件（phone.event.*）
  screen(on/off, fps, maxWidth, quality) → 投屏开关与参数
  input(kind, x, y, ...) → 电脑操控手机（tap/swipe/key/text）
```

**手机端帧处理**：`RemoteCmdWorker` 同时处理 `tool.invoke`、`screen.*`、`debug.*`；执行结果统一走
`tool.result` / `phone.event.tool` 回传，避免再开一套通道。

**安全边界**：
- `pc.exec_tool` / `debug.exec_tool` 只允许白名单工具（默认 `status/sessions/read_file/logcat/view_tree`）；
- `debug.exec_tool` 必须手机端二次确认；
- caps：手机端声明 `cmd.ui` + `link.rpc`；未声明 caps 的旧客户端不开放联动；
- 设备令牌吊销后联动立即失效（复用 `/devices/revoke`）。

## 4. 手机端 UI：不覆盖对话

1. **消息模型新增 `RemoteLinkPart`**（`parts` 体系里与 tool/reasoning 同级）：
   - 头：`🖥 电脑 · ask: "帮我查..."`，右侧状态点（排队/运行/完成/失败）
   - 体：流式文本（`link.delta` 追加）+ 子步骤列表（`link.tool`）
   - 尾：完成时展示耗时/工具数，点开可看完整结果
2. **模式开关**：聊天页顶部副标题右侧加一个"镜像/联动"切换（默认联动）。镜像模式才允许 `event` 全覆盖当前对话；联动模式只接收 `link.*` 与 `phone_ui`。
3. **`phone_ui` 插槽**照旧渲染在输入区上方；联动任务卡不进插槽，避免两套 UI 打架。

---

## 5. 电脑端 UI（插件面板）

在现有「📱 手机远程」面板新增「联动」段（`client.js`）：

- 当前 link 列表：`link_id / 来源 / 状态 / 耗时`，可取消；
- 「手机能力」段：`phone.catalog` 的工具目录（name/desc/level），`read` 级可直接"试跑"，`exec` 级提示"需手机确认"；
- 「本地事件」段：最近 `phone.event.*`（工具轨迹/agent 状态/错误），按时间倒序，可清空；
- 「屏幕」段：`screen.start/stop`、帧率/质量档位、`<canvas>` 实时帧 + 鼠标映射成 `screen.input`（需手机端已授权）；
- 「调试指令」下拉：`logcat / screenshot / view_tree` + 发送按钮，回传结果直接展示在面板里；
- 连接状态沿用 `/v2/pulse`（已修心跳判活），断线时这里显示"手机已断开"并停止下发。

| **P1** | **PhoneCli 解释器**：`cli.exec/stdout/stderr/exit` + 命令集 `help/version/tools list/show/call/ui dump/ui find/logcat/events`；电脑端 `phone_cli` 工具 + `dsh-phone` 本地 CLI；工具目录 `phone.catalog` + `phone.event.*` | 手机 `PhoneCli` + `RemoteCmdWorker` + 工具目录上报、`RemoteDshTool`（帧分发）、`index.js`（action/路由/环形缓冲）、`cli.mjs`、`client.js`（CLI 控制台 + 事件面板） |
| **P2** | 投屏与操控：`screen.start/stop/frame/input`、`/ws/screen` 通道、授权开关与前台约束 | 手机 `ScreenMirrorService`（MediaProjection）+ `RemoteCmdWorker` 输入注入、`index.js`（帧通道 + 限流）、`client.js`（canvas 渲染 + 鼠标映射） |
| **P3** | 镜像/联动模式切换、link 历史、面板联动段整合 | `AIChatActivity`（模式开关）、`ChatRemoteMode`（联动判定）、`client.js` |

P0 不需要动现有镜像链路，也不改 `ui_canvas`/`ui_component`；冲突面最小。

## 7. 验收标准（P0）

1. 手机 AI 调 `dsh_link(ask="列出电脑最近 3 个会话")` → 手机对话里出现一张「🖥 电脑 · 联动」卡，流式输出，**本地对话不被覆盖**；
2. 电脑面板能看到这条 link 的状态，可取消；
3. 断网 45s 内电脑端判离线（已有心跳修复），手机端卡状态变"电脑已断开"；
4. 旧客户端（无 `link.rpc` caps）行为不变，`remote_dsh` 原样可用。

**P1 验收**

5. 手机连接后上报 `phone.catalog`，电脑面板/`phone_tools(list)` 能看到手机工具目录（含参数 schema）；
6. `phone_tools(invoke, name="ui_component", args={...})` → 手机执行 → `tool.result` 回传；`exec` 级必须先弹手机确认，拒绝时返回 `denied`；
7. 手机工具调用产生 `phone.event.tool`，电脑面板按 `since` 能拉到，且**不包含**聊天正文/文件内容；
8. 关闭"回传本地事件"开关后，`phone.event.*` 立即停止（不缓存报复）。

**P2 验收**

9. 手机开启"允许电脑操控屏幕"后，电脑面板出现实时帧（≥2 fps），点按/滑动/返回键在手机上生效；
10. 切后台/锁屏/关闭授权 → 帧流停止，`screen.input` 被拒绝。
