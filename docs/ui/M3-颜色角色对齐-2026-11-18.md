# M3 颜色角色对齐（2026-11-18）

> 用户口径：「之前的主题色值可能有点问题，有些不是 m2 的颜色使用 m3 的颜色名称显示的不是 m3 的颜色」。

## 1. 根因

| # | 问题 | 后果 |
|---|---|---|
| 1 | 主题只声明了部分 M3 角色，`colorSurfaceContainer*`（五档）/ `colorOutlineVariant` / `colorInverse*` / `colorSurfaceTint` 缺失 | MDC 的 `MaterialDatePicker` / `MaterialTimePicker` / Chip / Card / Snackbar 读这组 attr，读不到退回 `colorSurface` 或透明 → "M3 名字、不是 M3 颜色" |
| 2 | `colorOutline` 映射到分隔线色 `#E2E8F0` | M3 的 outline 是组件描边（tone 50），浅灰描边在浅色面上几乎不可见（Chip/输入框/日期选择器） |
| 3 | 31 个预设 overlay 由 material-color-utilities 生成，自带完整 M3 角色 | 默认主题（无 overlay）与预设主题观感两套；默认主题是短板 |

## 3. 语义拆分

| attr | 语义 | 谁在用 |
|---|---|---|
| `colorOutline` | 组件描边 | `boxStrokeColor` / `strokeColor`（13 处）、Material 组件 |
| `colorOutlineVariant` | 分隔线 / 弱边框 | `android:background` 画细线（5 处布局，本次从 colorOutline 迁过来） |
| `colorBorder` | app 自己的边框语义 | 页面卡片描边（保持原值） |

> 不要把 `colorOutline` 再当分隔线用；也不要把 `colorBorder` 和 outline 混用——它们服务不同层。

## 3.5 预设主题怎么办（31 份生成 overlay）

`values/theme_overlays.xml` 是 **离线生成** 的（`tools/GenOverlays.java`，文件头写着"勿手改"）。

**2026-11-18 的最终落点**：由生成器把 M3 role 直接写进每套预设 overlay——五档
`colorSurfaceContainer*`、`colorOutlineVariant`、`colorSurfaceDim/Bright`、`colorInverse*`、
`colorState*` 都在生成产物里，每套预设都有自己的一整套，`ThemeManager` **不再叠任何兜底层**
（此前试过 `ThemeOverlay.App.M3Roles` 用 `?attr/colorSurfaceVariant` 兜底，但那会把五档容器
压回 2 档，已废弃）。

> 新增/调整预设色时改生成器再重生成，不要手改 `theme_overlays.xml`；
> `ThemePaletteTest` / `ThemeColorRolesTest` 会校验每套预设的容器层次不能塌成 2 档。
> 完整取值口径见 `docs/ui/主题色系-设计规范-2026-11-18.md`。

**2026-11-18 收口（第五批）**：每套预设再补 14 个状态语义 role ——
`colorError/colorOnError` + success/warning/info 各 4 件（base/on/container/onContainer）。
成功/警告/提示引用 `@color/*` 固定语义色（夜间由 values-night 自动切），错误色跟随该预设的
error 色板。现在 **31 套 × 46 role**，不再依赖基础主题兜底。

护栏：`PresetThemeRoleCoverageTest`（解析生成产物）钉住「31 套 / light-night 同名 /
每套 46 role / 同一样式无重复 item / surfaceContainer 恰好 5 档」。

生成流程（Windows 下同样适用）：只编 `ThemePalette` + `ThemePaletteProvider` + `mcu/**` +
`tools/GenOverlays.java`（整个 theme 目录含 Android 依赖，编不过），然后
`java -cp out GenOverlays src/main/res`；重跑后与旧产物做 item 级 diff 确认"只增不删"。

## 4. 验证

- `ThemeColorRolesTest`（Robolectric，4 例）：
  1. 浅色下 11 个 role 全部解析出非 0；
  2. `+night` 下同样全部解析出非 0；
  3. `outline ≠ outlineVariant`；
  4. surfaceContainer 五档明暗方向：浅色越低越亮、深色越高越亮。
- 真机：`ThemeAuditActivity`（`--es mode theme_audit`）目视核对 + 画布日期/时间选择器（M3 role 消费方）。

## 4.5 色系矩阵（2026-11-18 第二批：层级 / 状态 / 语义）

用户口径：「主题框架组件色系设完整了吗，感觉层级不够，看看 colors.xml」。

| 维度 | 角色（attr） | 浅色 | 夜间 | 组件入口（ComponentColors） |
|---|---|---|---|---|
| 表面 8 档 | `colorBackground` / `colorSurface` | #F8FAFC / #FFFFFF | #171221 / #1E1830 | `background()` |
| | `colorSurfaceContainerLowest…Highest` | #FFF/#F8FAFC/#F1F5F9/#E9EEF5/#E2E8F0 | #0F0C15/#171221/#1E1830/#251E38/#2D2545 | `surfaceContainer(0..4)` |
| | `colorSurfaceDim` / `colorSurfaceBright` | #E7E5EC / #FFFFFF | #110D18 / #3A3157 | `surfaceDim()` / `surfaceBright()` |
| 边框 | `colorOutline` / `colorOutlineVariant` | #79747E / #E2E8F0 | #938F99 / #2F2947 | `border()` / — |
| | `colorBorder` / `colorBorderStrong` | #E2E8F0 / #CBD5E1 | #3A3157 / #4A4166 | `border()` / `borderStrong()` |
| 状态 | `colorStateHover/Focus/Pressed/Dragged` | 8/12/12/16% onSurface | 同口径（白系） | `stateHover()` … |
| | `colorStateDisabledContainer/Content` | 4% / 38% | 同口径 | `stateDisabledContainer()` / `stateDisabledContent()` |
| 语义 | `colorSuccess/Warning/Error/Info(+Container/On…)` | 各 base + container + on | 同 | `success()/successContainer()/onSuccessContainer()` … |
| 图表 | `colorChart1..8` + `colorChartGrid/Axis/Label` | 系列色 + #E2E8F0/#94A3B8/#64748B | 系列色 + #3A3157/#8A82A0/#ABA2C6 | `chartColor(i)` / `chartGrid()` … |
| 遮罩 | `colorScrim` | #99000000 | #B3000000 | `scrim()` |

规则：
1. **层与层之间只用 token 递进**，不要在布局里写 `#FFFFFF` 或 `alpha 0.12`；
2. 组件要"抬高"用 `surfaceContainer(level)`，要"压低"用 `surfaceDim()`；
3. 按下/禁用用 `state*`，不要自己算 alpha；
4. 语义块 = `xxxContainer()` 底 + `onXxxContainer()` 字，不要 base 色配深字。

## 4.6 组件层接入（2026-11-18，第三批）

| 组件 | 改动 | 为什么 |
|---|---|---|
| `ComponentTheme.surfaceLayer(level)` | `surface` 上叠 `onSurface` 4/8/12/16% | 预设 overlay 只有 surface/surfaceVariant 两级，容器五档在预设下会退化；现场算保证任何主题都有层级 |
| `ComponentTheme.outline()` | 改读 `colorOutlineVariant` | `colorOutline` 已回归 M3 深描边，再拿它画卡片框会变深灰 |
| `ComponentTheme.success/warning/danger()` | 改走 `ComponentColors`（attr 优先） | 之前直接读固定资源，**换肤不跟** |
| `CardShell` 按压 | 自绘 `RippleDrawable`（`statePressed` + 卡片圆角 mask） | 不依赖机型 `selectableItemBackground`，按压色与按钮统一 |
| `AlertCardView` | 语义容器底 + on 色文字 + 语义色 33% 描边 | 四档级别在深浅/换肤下要能一眼区分 |
| `ChartCardView` | 网格 `chartGrid`、标签 `chartLabel` | 之前借 `border`/`textSecondary`，换肤后图表与卡片不同步 |

验收：`ComponentColorWiringTest`（5 例）钉住方向与取值；
真机看 alert 四档 / 图表 / 卡片按压。

## 6. 第四批（2026-11-18，色系收口）

> 追加口径（同日）：**默认选中蓝色**。只改默认选择，不改色值——`ThemeManager.DEFAULT_THEME_COLOR`
> = `COLOR_BLUE`；旧版本默认紫且没手动选过色的数据一次性迁移到蓝（`theme_color_picked` 标记）。
> 主题设置页因此默认高亮蓝色预设，`ThemeActivity` 无需另改。

审计口径与完整 token 表见 `docs/ui/主题色系-设计规范-2026-11-18.md`。本批修的关键错位：

- `colorDivider` 指到 `colorOutline` → 全站分隔线变深灰；改回 `colorOutlineVariant`。
- `colorBorderStrong` 指到聊天页 token、`colorScrim` 指到 `card_scrim`；改回主题语义色。
- `colorOnInfo` 被 `on_background` 覆盖 → 夜间 info 对比度 2.07；改回 `on_info` 并给 info 独立天蓝角色。
- `onSecondary/onTertiary/onSuccess/onWarning` 白字不达标 2.15~3.03；on 色改深色/语义 base 压到 600-700 档。
- 图表 `chart2/3/4` 白底 2.15~2.54；压到 600 档；图表轴/标签独立成角色。
- `R.color.outline`（历史细边框）映射到 `colorOutline` → 8 处 Java 1dp 描边变深灰；映射改到 `colorOutlineVariant`。
- `text_tertiary` 映射到 hint；新增 `colorControlTextTertiary`。
- 验收：`ThemeContrastTest`（16 组文字对 ≥4.5 + 图形 ≥3）、`ThemePaletteTest`（31 套种子角色有序）。
