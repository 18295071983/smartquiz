docs: correct backend facts and drop stale handover notes

The development docs still described two GPU backends and a 36 layer
offload, which stopped being true when the Hexagon NPU backend landed.

Corrections, each checked against source and the device:
- four backends (Hexagon / OpenCL / Vulkan / CPU), all linked statically
  into libllama-jni.so, default preference is hexagon
- auto resolves a single device with Hexagon first, then OpenCL, then
  Vulkan; passing several devices made model load segfault
- MAX_GPU_LAYERS is 64, and the 2B model offloads 43/43 layers to HTP0
- measured prefill: NPU about 1500 tok/s, OpenCL about 205 tok/s
- 14-cmake-build.md no longer claims -DGGML_VULKAN=OFF while the
  CMakeLists sets it ON, and it now documents the HEXAGON_* variables
  and why they must be CMake variables rather than environment variables
